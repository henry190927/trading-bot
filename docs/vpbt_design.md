> 狀態:**設計稿,等使用者審**。審過之前不寫程式。

## 0. 要驗證的說法

> 價格在成交量分佈的「山峰」之間穿梭:在山上會停留、在山與山之間的低量區走得快;
> 或是突破後直接穿出低量區,到下一座山。

使用者的範例(BTC 1h,2026-10-21):

```
上面那座山   約 82,500–83,000   POC50/POC100 ≈ 82,800
低量區       約 82,000–82,400
下面那座山   約 81,250–81,900   POC200 ≈ 81,531

單:81,700 掛多(下山的上緣)→ 目標 82,800(上山)· 停損 80,500
     風險 1,200 · 報酬 1,100 → 0.92R
停損若放在下山山腳下一點(約 81,200):風險 500 → 2.2R
```

**這份文件只做一件事:把這個說法變成可以回測、可以過 shipgate 的規則。**
不是要直接上線,也不是要推翻使用者的手動判讀。

## 1. 為什麼值得測,以及跟之前被否決的東西差在哪

| 之前測過的 | 結果 | 跟這次的差別 |
|---|---|---|

教訓沿用:**只有事件會計分,距離不會**(記憶:proximity votes don't score)。
所以這次的進場一定要綁一個**事件**(收盤回到山內、或收盤突破進入低量區),不能只是「價格靠近山邊」。

## 2. 核心定義:什麼是「一座山」

現有的 `indicator.BuildVolumeProfile` 只給 bins + POC + 前 N 個 HVN(成交量最大的幾個格子),
**沒有「山」的概念**。所以需要一個新函式把分佈切成節點:

```go
// Node 是成交量分佈裡的一座「山」:一段連續、成交量明顯高於周圍的價格區間。
type Node struct {
    Low, High float64 // 山腳到山腳的價格範圍
    POC       float64 // 這座山裡成交量最大的價位
    Volume    float64 // 這座山的總成交量
}

// FindNodes 把成交量分佈切成由低到高排列的山。
func FindNodes(vp indicator.VolumeProfile, opts NodeOpts) []Node
```

建議的演算法(**這是留給你寫的部分**,見第 7 節):

```
1. 平滑:對 bins 的成交量做 3 格移動平均,去掉單一格的雜訊
2. 找峰:局部最大值,而且「突出度」≥ 全圖最大值的 P%(預設 25%)
3. 找山的邊界:從峰往兩側走,直到
     · 成交量 < 峰值的 E%(預設 40%),或
     · 走到兩座峰之間的谷底(兩座山共用一個谷時,以谷底為界)
4. 低量區(LVN):相鄰兩座山之間的谷,「深度」= 谷底量 ÷ 較矮那座峰 < D(預設 0.5)
   才算真的低量區;不夠深的兩座峰當成同一座山
```

參數只留三個(P、E、D),而且第一輪只跑預設值。
**參數越多,回測越容易「找到」一組其實是雜訊的好結果。**

## 3. 進場:兩個要分開測的 arm

兩個 arm 都只在**已收盤的 K 線**上判斷,分佈只用**訊號那根之前**的 K 線建立(沒有 look-ahead)。

### Arm A — 山邊守住(使用者範例的那種)

```
做多:價格從上方回落,影線碰到山的上緣(High),
      而且這根 K 收盤回到上緣之上  → 收盤價進場做多
做空:鏡像,價格從下方反彈碰到山的下緣,收盤跌回下緣之下
```

### Arm B — 突破穿越

```
做多:前一根收盤還在山內,這一根收盤突破山的上緣、進入上方的低量區 → 做多
做空:鏡像
條件:上方必須真的有下一座山(否則沒有目標)
```

### 兩個 arm 共用的規則

```
停損   山的另一側山腳外 + 0.25×ATR(14)    ← A:下緣下方;B:回到山內的中點(要再討論)
目標   下一座山的「近側山腳」              ← 保守:一進入下一座山就出
       (對照:下一座山的 POC,當成第二組參數)
R 下限  目標距離 ÷ 停損距離 < 1.5 就不進場
冷卻   同一座山被用過之後,價格離開這座山前不再進場
```

## 5. 預期會遇到的坑

1. **分佈的回看長度決定一切。** 100 根和 200 根 K 線畫出來的山完全不同(截圖裡 POC50/100 在上山、POC200 在下山就是這個現象)。第一輪固定 200 根(跟 POC200 一致),再拿 100 根當對照。
2. **山的邊界本身是估計值。** 「碰到上緣」要有容忍度(預設 0.15%),否則幾乎永遠剛好差一點。
3. **趨勢中山會一直被吃掉重畫。** 強趨勢時舊的山很快失效。可能需要「趨勢方向過濾」——但這是第二輪才加的東西,第一輪先看原始版本有沒有 edge。
4. **Arm A 跟 range-edge 很像**(都是在區間邊緣反向進場)。如果 A 的結果跟 range-edge 高度重疊,它就不是新的 edge,只是同一筆錢算兩次。報告裡會列兩者進場時間的重疊率。
